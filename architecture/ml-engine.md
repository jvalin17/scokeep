# Architecture: Self-Evolving ML Engine

> Generated by /architecture on 2026-09-01
> Reviewed by: ML Engineer (opus), Research Engineer (opus), Architect (opus)

## Problem

1. Two separate feature extraction passes iterate rounds independently with overlapping logic
2. Insights recompute on every stats page load (should be cached from game finish)
3. Titles are 40 hardcoded Python functions — simple ones should be declarative config
4. Personality centroids are hardcoded — should auto-calibrate via Welford
5. No shared metric vocabulary between career and per-game engines

## Key Decision: Compute Once on Game Finish

Insights (personalities, titles, career records, highlights) are computed ONCE when a game finishes via `compute_insights()`. The stats endpoint returns the cached JSONB blob. No recomputation on page load.

## Module Architecture

```
app/services/
  round_utils.py          (~16 lines)  — shared _iter_round_bids
  metrics.py              (~250 lines) — shared metric computation (single pass)
  metric_aggregator.py    (~120 lines) — career aggregation from per-game metrics
  personality_engine.py   (~200 lines) — centroids, similarity, assignment, Welford
  title_registry.py       (~80 lines)  — declarative title defs + evaluator protocol
  title_patterns.py       (~300 lines) — complex title evaluator functions
  insights.py             (~300 lines) — orchestrator: load, pipeline, store
  analytics.py            (~300 lines) — career records, game history
```

## Shared Metric Layer (metrics.py)

Single pass produces `GameMetrics` containing `PlayerGameMetrics` per player:
- Accuracy, overbids, underbids, off-by-one
- Weighted accuracy (card-count weighted)
- Zero bids, streaks, tempo, trump accuracy
- Round scores, cumulative scores, bid sequences
- Best bid, cards per round, trump per round

Both engines consume this:
- **Career engine:** `metric_aggregator.aggregate_career()` sums per-game metrics → 10-d vector
- **Title engine:** `title_registry.evaluate_all_titles()` evaluates against GameMetrics directly

## Declarative Title System

Two tiers:
- **~18 simple titles:** Config dict with metric name + rank mode + threshold
- **~22 complex titles:** Evaluator functions in title_patterns.py

```python
# Declarative
title("champion", "🏆", "Champion", "Highest total score",
      metric="total_score", rank="highest", score_weight=100)

# Complex (evaluator function)
@title_fn("comeback_king", "👑", "Comeback King", "Was last, finished top 2")
def comeback(gm: GameMetrics) -> list[dict]: ...
```

## Title Count Formula

```python
total = clamp(2 * num_players, 4, 14)
```

Coverage guarantee: every player gets ≥1 title in Phase 1.

## Auto-Calibration (Welford Accumulators)

Per-playground, stored in `insights["_calibration"]`:
```json
{"welford": {"count": 47, "mean": [...], "m2": [...]}}
```

- Updated on each `compute_insights()` call from raw feature vectors
- Used by `adaptive_z_normalize()` when count ≥ 20, falls back to GLOBAL_PRIORS below that
- Centroids stay FIXED (they define archetype meaning) — only normalization adapts

## Performance Budget

50 games × 8 players × 24 rounds = 9600 data points
- Metric computation: ~2ms
- Career aggregation: ~0.5ms
- Normalization + assignment: ~0.1ms
- Title evaluation: ~1ms
- Total: <10ms (well under 100ms budget)
