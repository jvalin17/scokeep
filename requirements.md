> Generated by /requirements on 2026-07-25
> Mode: standard
> Scope: app
> Project state: greenfield

## Problem Statement

When playing Kachuful (Judgement) with physical cards, scores are tracked in a notebook. Mistakes happen — wrong scores, miscalculations, lost notebooks. Need a mobile-friendly web app that replaces the notebook with fast, error-free score tracking.

## Core Requirement

**Blind, fast score entry** — the person entering scores must NOT see previous totals or other players' bids. Speed matters (nobody wants to wait between rounds). The scorekeeper has zero responsibility beyond asking "how many hands?" and tapping a number.

## Boundaries

- **Excluded (v1):** No card game logic (no dealing, no trick-taking, no AI). This is a scorer, not a game.
- **Excluded (v1):** No user accounts/auth — share code is the only gate.
- **Constraints:** Free hosting (Render), lightweight DB, PWA for mobile feel.
- **UI:** Minimalistic but polished and lovable — not just lightweight.
- **No player colors** — keep it clean, not a rainbow.

## User Stories

- As a scorekeeper, I want to create a playground with a funky name so my group has a persistent home for all our games.
- As a player, I want to join a live game by share code so I can take over scoring if needed.
- As a returning player, I want to access my playground by name + PIN to start a new game or see past games.
- As a scorekeeper, I want to enter bids quickly via a phone-style keypad (player names appear one by one) so the game isn't slowed down.
- As a scorekeeper, I want to enter actual hands won at round end — just ask each player "how many?" and tap the number.
- As a player, I want the app to NOT show me anyone's bids or totals during play (expert mode).
- As a player, in friendly mode I want to see all details (bids, scores, trump) in a cool, readable format.
- As a group, I want flexible scoring rules so we can use our house rules or play other games.
- As a group, I want to choose how many sets to play and extend or finish early at any point.

## Game Structure

- **Set:** 8 rounds → cards go 8,7,6,5,4,3,2,1
- **Default:** 3 sets (24 rounds total: 8→1, 8→1, 8→1)
- **Extendable:** At end of any set, players can add another set or end the game
- **Early finish:** Can end game at any point between rounds
- **Trump rotation:** ♠→♦→♣→♥ repeating across rounds

## Primary User Flow

1. **Create Playground** → Enter player names → Get shareable share code
2. **Configure** → Select game mode, scoring rules, number of sets (default 3)
3. **Round Start** → App shows round number, cards this round (mode-dependent: trump suit)
4. **Bidding Phase** → Queue: player name appears → scorekeeper taps phone keypad (0-8) → number shown for 10s (can change) → auto-advances → blind in expert/rookie
5. **Confirm Bids** → Summary of all bids shown → "Start Round" or go back to edit any player's bid
6. **Play Phase** → Screen shows mode-appropriate info. Expert: cards dealt only. Rookie: trump + over/underbid. Friendly: everything.
7. **Round End** → Scorekeeper taps "End Round" → Queue: "How many hands did [Name] make?" → keypad entry → 10s to change → auto-advances → warn if total ≠ cards dealt but allow it
7. **Set End** → Option to extend (add another set) or finish game
8. **Scoreboard** → Only visible between rounds (or at game end), shows cumulative scores

### Design Direction
- **Style:** Minimalistic but polished and lovable. Clean, no clutter.
- **No player colors** — monochrome palette, elegant.
- **Primary interaction:** Phone-style keypad (0-8), large thumb-friendly buttons
- **Trump display:** Prominent, heavy/bold suit icons (not plain Unicode fills — explore CSS/SVG options)
- **Suit styling:** TBD — will explore heavy, premium-feeling suit icons during implementation

### Responsive Targets
- **Primary:** Mobile (phone held by scorekeeper)
- **Breakpoints:** Mobile-first

### Interaction Patterns
- Phone keypad: 3×3 grid + 0 row (like phone dialer), confirm button
- Greyed-out keys: invalid bids for dealer (should)
- Queue: player names appear one at a time
- 10s review: show entered number large, tap to change, auto-advances after 10s
- Confirm screen: after all bids entered, show summary with edit option before starting round

## Assumptions

- SQLite or Neon Postgres (same as Frenmo) — free tier sufficient
- FastAPI + Jinja templates (same stack as Frenmo) for speed of development
- No WebSockets needed — one phone is the controller, share code is for recovery/handoff only
- Trump rotation is fixed (♠→♦→♣→♥) but could be overridden
- Max bid value is 8 (max cards in a round), so phone keypad (0-8) covers all cases
